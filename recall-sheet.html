1 "Where does it go?" — config

Tool permissions / allowed tools — CLAUDE.md or settings.json?
settings.json → permissions.allow. Not CLAUDE.md.
Hooks — CLAUDE.md or settings.json?
settings.json (hooks key). CLAUDE.md can't run anything.
Env vars, MCP servers, model choice?
settings.json — it's all configuration.
Coding standards, architecture, conventions, build cmds?
CLAUDE.md — it's instructions/context.
What runs deterministically, regardless of Claude's decision?
Hooks. CLAUDE.md is only context — Claude may ignore it.
Which config wins: enterprise or user?
Enterprise/managed — top of precedence.
settings.json precedence, high → low?
Managed › CLI --settings › settings.local.json › settings.json › ~/.claude/

3 Context window — the 3 levers

Name the 3 ways to handle long context.
Caching (reuse) · Context editing (clear) · Compaction (summarize).
Which one summarizes old context?
Compaction (compact-2026-01-12, ~150K trigger).
Which one deletes old tool results / thinking?
Context editing → clear_tool_uses_20250919, clear_thinking_20251015.
Context window: Opus 5 / Sonnet 5? Haiku 4.5?
1M tokens · Haiku 4.5 = 200K.
Compaction gotcha — what must you re-send each turn?
The full response.content (compaction blocks included) — text-only loses state.

4 Prompt caching

Cache type value?
"cache_control":{"type":"ephemeral"}
Default TTL? Extended?
5 min default · 1h via "ttl":"1h".
Max breakpoints per request?
4
Prefix / render order?
tools → system → messages. Stable first, volatile last.
How do you confirm a cache hit?
usage.cache_read_input_tokens > 0 (write = cache_creation_input_tokens).
What silently invalidates it?
Any byte change in the prefix — datetime.now(), unsorted JSON, a changed tool list.

5 Tools & tool_choice

Default tool_choice?
{"type":"auto"} — Claude decides.

{"type":"any"}
Force one specific tool?
{"type":"tool","name":"…"}
Forbid tools?
{"type":"none"}
Limit to one tool per turn?
"disable_parallel_tool_use":true (on any tool_choice).
Where does strict:true go?
On the tool definition — not tool_choice. Needs additionalProperties:false.
Returning multiple parallel results?
All tool_result blocks in one user message.
Signal a tool failure?
tool_result with "is_error":true.

8 Agent SDK

Package names (py / ts)?
claude-agent-sdk / @anthropic-ai/claude-agent-sdk (renamed).
What does query() return?
An async iterator of messages (async for / for await).
Options object?
ClaudeAgentOptions(…) — system_prompt, model, permission_mode, max_turns.
Multi-turn / persistent client?
ClaudeSDKClient — .query() then .receive_response().
Agent SDK vs Tool Runner?
Different. Tool Runner = client.beta.messages.tool_runner in the API SDK.
async for msg in query(prompt="…",
    options=ClaudeAgentOptions(model="sonnet",
        permission_mode="acceptEdits")): ...

9 -p · JSON · pydantic

Run Claude Code headless?

--output-format values?
text · json · stream-json
In JSON output, where is the answer?
The "result" field (also session_id, total_cost_usd, usage).
Pydantic structured output (API)?

Raw JSON schema instead of a class?

Deprecated way?
Top-level output_format string param — don't use.

⏱ Turn lifecycle — hook firing order (prompt → PreToolUse → down)

Top-level events fire top→bottom. The dashed block (PreToolUse → tool → PostToolUse) repeats once per tool call. Colored edge = can block / runs after.

Also, off the main line: SubagentStop (a Task subagent finishes) · Notification (permission prompt / idle) · PreCompact → PostCompact (around compaction) · SessionEnd (session closes).
What fires first when you submit a message?
UserPromptSubmit (after SessionStart at session open).
Which hook can block a tool before it runs?
PreToolUse — deny or ask.
Which fires after a tool returns (to format/validate)?
PostToolUse.
Which fires when Claude finishes the whole answer?
Stop (StopFailure if it errored).
Which fires when a spawned subagent finishes?
SubagentStop.
Which fires just before context is compacted?
PreCompact.

! "If you see this on the exam…" — traps

budget_tokens on Opus 5/4.8/4.7/Sonnet 5/Fable → 400. Answer: thinking:{"type":"adaptive"}.
temperature / top_p / top_k on those models → 400. Remove them.
Assistant prefill (4.6+ family) → 400. Use structured output instead.
effort is inside output_config, not top-level. Values low·medium·high·xhigh·max.
Bad model ID → 404, never 400. No date suffix: claude-sonnet-4-6, not …4.6.
Retryable = 429 / ≥500 / network only. 4xx (400/401/403/404/413) never retry.
strict:true → on the tool def, not tool_choice.
Parallel tool_results → all in ONE user message.
MCP API connector = two halves + beta header. One alone = validation error.
Cache invalidation = one byte in the prefix. Verify via cache_read_input_tokens.
Tools/permissions/hooks → settings.json. CLAUDE.md is context only.
Agent SDK ≠ Tool Runner. Package renamed to claude-agent-sdk.
output_format = pydantic class on .parse(); old top-level string is deprecated.
≥128K max_tokens requires streaming or you hit an HTTP timeout.
display defaults to "omitted" — thinking is silent unless you set "summarized".
